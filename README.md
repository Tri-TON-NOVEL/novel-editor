## パソコンでも、スマートフォンでも。同じアプリで、物語を綴っていく。

こんなことで困っていませんか？

腰を据えて物語と向き合うときは、自宅のパソコンで。  
電車でのちょっとした合間には、スマートフォンで。  
外出先で少しまとまった時間ができたら、タブレットで。

場所や端末が変わっても、同じ小説の続きを、同じ使い勝手で編集したい。

**「あや綴り」は、「小説家になろう」「アルファポリス」に対応した、ブラウザで動く小説執筆アプリです。**

作品、章、エピソード、プロット、メモなどをまとめて管理できます。Windows・Mac・iPhone・iPad・Android のブラウザで利用でき、ホーム画面に追加すればアプリ（PWA）としても使えます（Android は実機でのテストをしていません。[動作環境](#動作環境)を参照）。

端末間でバックアップを共有するには、Google Drive または OneDrive のドライブ接続を設定し、各端末で同じバックアップ保存先を選びます。これにより、バックアップを介して別の端末でも同じ作品の続きを編集できます。

場所や端末が変わっても、同じアプリで物語を綴っていく。  
「あや綴り」は、そんな使い方を目指しています。

## 主な特徴

### 1. 「なろう用」と「アルファポリス用」の原稿を別々に管理できる

一つのエピソードに、投稿サイトごとの本文と複数の稿を保存できます。

現在編集中の稿だけを別サイト用へコピーし、ルビ・傍点・挿絵などの記法も変換できます。

### 2. パソコン、スマートフォン、タブレットで同じアプリを使える

Windows、Mac、iPhone、iPad、Androidのブラウザーで動作し、PWAとしてホーム画面にも追加できます。

Google DriveまたはOneDriveのバックアップを介して、別の端末から続きを編集できます。

※端末間でバックアップを共有するには、Google DriveまたはOneDriveの設定が必要です。

### 3. 使う端末ごとに、執筆画面を自分仕様にできる

簡易表示と詳細表示を用意し、それぞれの表示内容を利用者が設定できます。

パソコンでは情報量の多い画面、スマートフォンでは必要な入力欄とボタンだけの画面など、端末に適した執筆環境を作れます。

また、テキスト入力欄を最大化できるため、スマートフォンなどの画面の小さい端末でも、文章を書くスペースを大きく取れます。

### 4. エピソードごとに、本文・プロット・フリーメモをまとめて残せる

各話の本文だけでなく、その回のプロット、修正事項、思いつきなどを一緒に保存できます。

前書き・後書きや活動報告も、そのエピソードに結び付けて管理できます。

例えば、先にエピソードのプロットを書いておき、それを確認しながら本文を書き進めることができます。

> **物語を書く場所と、その回について考える場所を、エピソードごとにひとつにできます。**

### 5. 作品から一話ごとの執筆情報まで、階層的に管理できる

作品、章、エピソードに加えて、あらすじ、全体プロット、世界観・用語、登場人物、作品全体のメモを一つの環境で管理できます。

### 6. サイトごとに複数の稿を残しながら改稿できる

第1稿、第2稿という形で以前の原稿を残しながら、新しい稿を編集できます。

なろう用とアルファポリス用の稿は独立しているため、それぞれ異なる段階で改稿を進められます。

### 7. 投稿サイトのTXTを、章とエピソードに分けて取り込める

「小説家になろう」「アルファポリス」から出力したTXTを解析し、章とエピソードに分割して取り込めます。

自動判定だけでなく、区切り位置の手動修正、プレビュー、重複確認、UTF-8・Shift_JISの判定にも対応しています。

### 8. 必要な情報を選び、一つのバックアップファイルにまとめられる

次のような情報を選択し、バックアップパックとして一つのファイルに保存できます。

- 環境設定
- 全作品
- 作品単体
- 作品資料
- 選択したエピソード

復元する前に、バックアップの内容を確認することもできます。

### 9. 端末内保存、変更履歴、端末外バックアップを使い分けられる

最新状態は常にブラウザー内へ保存されます。

さらに、端末内の変更履歴と復元ポイント、Google Drive・OneDrive・端末フォルダーなどへの自動バックアップを利用できます。

### 10. エピソードごとの活動報告まで管理できる

Xの投稿文となろうの活動報告を、エピソードごとに保存できます。

作品URL、話数、タイトルを使ったひな型にも対応しています。

### 11. 小説執筆に必要な入力補助を備えている

ルビ、傍点、挿絵、記号、字下げ、一括置換、文字数表示、画像一覧、入力欄の最大化や折りたたみなどを利用できます。

本文を最大化したときに表示するボタンも、一つずつ選択できます。

### 12. 世界観・用語と登場人物を表形式で整理できる

検索、所属分類、同一人物の別名管理、必要な行や列を選んだテキスト出力などに対応しています。

### 13. 原稿を外部サーバーへ送らずに使い始められる

通常の作品データは、使用している端末のブラウザー内に保存されます。

Google DriveやOneDriveを使用すると決めた場合だけ、クラウドへバックアップします。

## 動作環境

**Google Chrome をおすすめします。** どの端末でも Chrome で開くと、動作と画面がいちばんそろいます（作者は主に Chrome で確かめています）。

| 端末 | おすすめ | ほかに使えるブラウザ | 補足 |
|---|---|---|---|
| Windows・Mac | **Chrome** | Edge、Safari（Mac） | Chrome・Edge は保存先を選ぶ画面が使え、自動バックアップの保存先に「フォルダ」（ネットワークドライブも可）も選べます。Mac の Safari は保存が「ダウンロード」フォルダへ、自動バックアップは Google ドライブか OneDrive |
| iPhone・iPad | **Chrome** | Safari | 保存は共有メニュー（「"ファイル"に保存」）。自動バックアップは Google ドライブか OneDrive（iCloud には自動で保存できません）。ホーム画面に追加してアプリとしても使えます |
| Android | **Chrome** | — | 自動バックアップは「フォルダ」（端末内）か Google ドライブ・OneDrive。**実機でのテストはしていません** |

- **Android は実機でのテストを行っていません。** 機種やブラウザによっては、動かない・表示が崩れるなどの場合があります。
- 同じ端末でも、ブラウザごと（Chrome と Safari、ブラウザとホーム画面のアプリ）に作品データと設定は別々です。ふだん使うブラウザを1つに決めておくと迷いません。

## データの保存先とプライバシー

- 作品は**使っている端末のブラウザの中（IndexedDB）**に保存されます。サーバーには送りません。
- 外部に送るのは、自分で Google ドライブか OneDrive を使うと決めたときだけです（使うクラウドは端末ごとに1つ選びます）。
  - Google ドライブの権限は `drive`（ログインした人のマイドライブ全体）です。
  - OneDrive の権限は `Files.ReadWrite`（ログインした人の OneDrive のファイル）と `offline_access`（ログインを自動で更新するため）です。
  - このソフトは使う人専用で、各自が自分で登録したクライアントID で、自分のクラウドに使う前提です。
  - エディターが消すのは、自分の端末のプレフィックスの古い自動バックアップだけです。
- iPhone・iPad では、Safari で開いたときとホーム画面のアプリで開いたときで、データが別々になります。
- ブラウザのデータを消すと、作品も消えます。**自動バックアップ**か、「ファイル」→ 全体の「名前を付けて保存」で、こまめに残してください。

## はじめかた

1. [https://tri-ton-novel.github.io/novel-editor/](https://tri-ton-novel.github.io/novel-editor/) を **Chrome** で開きます。
2. （任意）アプリとして使うときは、ホーム画面に追加します。
   - iPhone・iPad：Chrome の共有ボタン（アドレスバーの右）→「ホーム画面に追加」（Safari なら共有 →「ホーム画面に追加」）
   - Android：Chrome のメニュー →「アプリをインストール」
   - Windows・Mac：Chrome のアドレスバーの右の「インストール」ボタン
3. 「設定」→「バックアップ」→「サーバへの自動バックアップ」で保存先を選んでおくと安心です。複数の端末で使う場合はクラウド（Google DriveかOneDrive）がおすすめです。
   - 利用するクラウドと接続IDは「設定」→「クラウド」で指定します（端末ごと）。ファイルとバックアップの保存先は、それぞれのタブで選びます。
   - バックアップ先のフォルダは**自分で作って選びます**（名前は自由。「フォルダを選ぶ・作る」の画面で作ることもできます）。選んだフォルダに直接保存し、選ぶまでは保存しません。
   - 端末どうしで同期するときは、すべての端末で同じクラウド・同じフォルダを選びます（PC は、パソコン版 Google ドライブ・OneDrive の中のそのフォルダを「フォルダ」方式で選んでも同期できます）。
   - PC の「フォルダ」方式では、ネットワークドライブ（NAS など）のフォルダも選べます。
4. クラウドを使う場合は、下の「[Google ドライブを使うための準備](#google-ドライブを使うための準備)」か「[OneDrive を使うための準備](#onedrive-を使うための準備)」を最初に1回だけ行います。

- 新しい版が出たら、各端末で一度再読み込みします（ホーム画面のアプリは閉じて開き直します）。

## Google ドライブを使うための準備

最初に1回だけ必要です。Google ドライブを使わないなら不要です。

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作り、[Google Drive API](https://console.cloud.google.com/apis/library/drive.googleapis.com) を有効にします。
2. 「Google Auth Platform」で、次の3つを設定します。
   - [ブランディング](https://console.cloud.google.com/auth/branding)：アプリ名・サポートメール
   - [対象](https://console.cloud.google.com/auth/audience)：「外部」・「テスト中」のまま、テストユーザーに自分の Gmail
   - [データアクセス](https://console.cloud.google.com/auth/scopes)：スコープ `https://www.googleapis.com/auth/drive`（「スコープを追加または削除」→ 一覧の下の「スコープを手動で追加」に貼り付け）
3. [クライアント](https://console.cloud.google.com/auth/clients) → **ウェブ アプリケーション** を作り、次の2つを登録します。
   - **承認済みの JavaScript 生成元**：`https://tri-ton-novel.github.io`
   - **承認済みのリダイレクト URI**：`https://tri-ton-novel.github.io/novel-editor/`（最後の `/` まで同じにします）
     - ホーム画面のアプリや、ポップアップが開けないときは、ページごと Google に移動してログインし、この URI に戻ってきます。
     - 登録がないと `redirect_uri_mismatch` になります。
4. エディターの「設定」→「クラウド」で、使うクラウドを「Google ドライブ」にし、表示された **クライアントID** を入れて保存します。
   - すべての端末で同じクライアントID・同じ Google アカウントを使えば、どの端末で保存したファイルも、ほかの端末から開けます。

- ログインのとき「Google はこのアプリを確認していません」と出ます。自分で作ったアプリなので「詳細」→「（安全ではないページ）に移動」で進み、ドライブへのアクセスを許可してください。
- アプリが「テスト中」の間は、約7日ごとにログインし直す必要があります。
- 1回のログインは約1時間で切れます。切れると画面の上にログインのボタンが出ます。

## OneDrive を使うための準備

最初に1回だけ必要です。OneDrive を使わないなら不要です。Google ドライブと同じく、自分専用のアプリを登録して、その **アプリケーション（クライアント）ID** をエディターに入れます。サーバーやクライアント シークレット（秘密の鍵）は要りません。

1. [Microsoft Entra 管理センター](https://entra.microsoft.com/)（または [Azure portal](https://portal.azure.com/)）に、OneDrive を使う Microsoft アカウントでサインインします。
   - 個人の Microsoft アカウント（outlook.jp・hotmail.com など）でも登録できます。初めてのときは、ディレクトリや無料の Azure アカウントの作成を求められることがあります。
2. 「**アプリの登録**」→「**新規登録**」で、次のように入れて「登録」します。
   - **名前**：自由（例：あや綴り）
   - **サポートされているアカウントの種類**：「**任意の組織ディレクトリ内のアカウントと個人用の Microsoft アカウント**」
   - **リダイレクト URI**：プラットフォームに「**シングルページ アプリケーション (SPA)**」を選び、`https://tri-ton-novel.github.io/novel-editor/`（最後の `/` まで同じにします）
     - 「Web」で登録すると、ログインの最後に `AADSTS9002326` のエラーになります。その場合は「認証」で「シングルページ アプリケーション」として登録し直してください。
     - 登録がないと、Microsoft のページで `redirect_uri` が違うというエラーになります。
3. 登録したアプリの「**API のアクセス許可**」→「アクセス許可の追加」→「Microsoft Graph」→「**委任されたアクセス許可**」で、次の2つを追加します。
   - `Files.ReadWrite`
   - `offline_access`
4. 「**概要**」に表示された「**アプリケーション (クライアント) ID**」をコピーします。
5. エディターの「設定」→「クラウド」で、使うクラウドを「**OneDrive**」にし（画面を読み直します）、「OneDrive の接続の設定」に ID を入れて保存します。
   - すべての端末で同じ ID・同じ Microsoft アカウントを使えば、どの端末で保存したファイルも、ほかの端末から開けます。

- ログインは、いったん Microsoft のページに移動して行い、終わるとエディターに戻ってきます（書きかけの内容は移動の前に保存します）。最初のログインでは、アクセスの許可を求める画面が出ます。
- ログインは約1日続きます（1時間ごとの更新は、画面を出さずに自動で行います）。切れると画面の上にログインのボタンが出ます。
- 大きなバックアップ（4MB 超）も、分けて送るので保存できます。

## 開発

### ファイル構成

| ファイル | 内容 |
|---|---|
| `index.html` / `styles.css` | 画面 |
| `js/app.js` | 画面の動作・自動保存・章とエピソード・ファイル・設定など |
| `js/format.js` | 作品のデータ形式（v3）・旧形式からの移行・文字数 |
| `js/notation.js` | なろう／アルファの記法と変換・挿絵・X の文字数・ひな型 |
| `js/importer.js` / `js/importui.js` | TXT インポートの解析と画面 |
| `js/tables.js` | 分類つきの表（設定・登場人物）と全体プロット |
| `js/db.js` | 端末内保存（IndexedDB） |
| `js/backup.js` / `js/sync.js` | 全体・エピソードのファイル形式と復元／自動バックアップと同期 |
| `js/localfile.js` | 端末のファイルの読み書き（保存先を選ぶ画面・共有メニュー・ダウンロード） |
| `js/dialogs.js` | 確認・入力・選択の画面（どの OS でも同じボタンの並び） |
| `js/providers/` | クラウド接続（`gdrive.js`：Google ドライブ、`onedrive.js`：OneDrive、`index.js`：使うクラウドの切り替え） |
| `sw.js` / `manifest.webmanifest` | オフライン対応・ホーム画面アイコン |
| `docs/` | 使い方と、改修の記録 |
| `tests/` | 自動テストとサンプル TXT、OneDrive のテスト用の偽物（`mock_onedrive.js`） |

- フレームワークやビルドは使っていません。HTML・CSS・JavaScript（ES モジュール）だけで動きます。
- 更新したときは、`sw.js` の `VERSION` と `js/app.js` の `APP_VERSION` を上げてください（各端末に新しい版が届くようにするため）。
