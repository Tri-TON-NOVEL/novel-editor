# 保存形式の比較（7.7.0 調査・評価のみ）

改良依頼の項目15（通常のファイル保存・読み込みと、バックアップの形式の比較）の調査結果です。
**今回は確認・評価のみで、保存形式は変えていません。**（7.7.0 で足したのは、バックアップパックの一覧表示・ファイル名用の管理情報 `meta` と、環境の `cloud`・`clientIdIncluded` だけです。どれも読み込みには使わず、前の版のファイルにない場合も今までどおり読めます。）

## 3. 評価

**よいところ**

- どの形式も `format` と版を持ち、新しすぎるファイルは読み込まないので、形式が変わっても判別できる。
- 全体バックアップは読み込み時にバックアップパックへ変換して同じ確認画面を通るので、読み込みの処理はすでに一本化されている。
- 作品・エピソードの同一性はファイル名ではなく `workId`・エピソードの `id` で判断している。

**気になるところ**

- エピソードファイルには稿・活動報告・エピソードの `id` が入らないため、バックアップの代わりには使えない（別の端末で同じエピソードとして扱えない）。
- 作品ファイルにも稿・変更履歴が入らない。
- 「全体を開く」はバックアップパックを読めず、「バックアップパックを確認・読み込む」は作品ファイルを読めない。どのファイルをどこから開くかを利用者が覚える必要がある。
- 作成したアプリの版（`appVersion`）が入るのはバックアップパックだけ。

## 4. 統一するか（提案）

保存の形を一つにまとめるなら、**バックアップパック（`ayatuzuri-backup-pack`）にそろえる**のがよいと考えます。項目の組み合わせで「作品1つ」「1話」「すべて」をそのまま表せ、稿・環境・管理情報も持てるためです。

進め方の案（実施する場合は、別の依頼として行う）：

1. **読み込み口の統一**（形式は変えない）：どの「開く」でも4形式すべてを受け付け、中身に合わせて適切な画面へ回す。作品ファイル・エピソードファイルも、読み込み時にパックへ変換して確認画面を通す。
2. **保存の統一**：「エピソードを名前を付けて保存」「全体を名前を付けて保存」も、中身をバックアップパックで書き出す（エピソードは稿・活動報告・`id` 付きになる）。
3. **前の形式は読むだけ残す**：作品ファイル・エピソードファイル・全体バックアップの読み込みは、ずっと残す。

1 は形式を変えずにできるので、統一するなら 1 から始めるのが安全です。2 は書き出したファイルを前の版のあや綴りで開けなくなるため、全端末を更新してから行う必要があります。
