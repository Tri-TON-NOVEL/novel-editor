# Phase 1 データ形式 v3 と移行仕様

## ファイル形式
```json
{ "format": "novel-editor", "version": 3, "schemaVersion": 3, "project": { ... } }
```
`version` は旧版の読込処理との互換のため `schemaVersion` と同じ値を残す。

## project の変更点（v2 → v3）
| 項目 | v2 | v3 |
|---|---|---|
| `workId` | なし | 作品の識別子（UUID）。端末・ファイルをまたいで同じ。重複確認・Drive 照合に使う |
| `site` | 投稿先（記法の切替） | **メイン投稿サイト**（`narou` / `alpha`）。値・名前は変更なし（仕様書の `alphapolis` は内部名 `alpha`） |
| `chapters[]` | 全体プロットの章 `{id,title,plot}` | 同じ配列を「章」とする（A方式）。保存時に `order` を付ける |
| `episodes[].title/foreword/body/afterword` | エピソード直下 | **廃止** → `drafts.narou` / `drafts.alpha` へ |
| `episodes[].drafts` | なし | サイト別原稿 `{ title, foreword, body, afterword }` |
| `episodes[].chapterId` | なし | 所属章の ID。`null` は未分類 |
| `episodes[].freeMemo` | なし | フリーメモ（サイト共通） |
| `episodes[].order` | なし | 保存時に配列の順で付ける |

## 旧データの補完規則
| 新項目 | 補完値 |
|---|---|
| `drafts` | 旧 `title/foreword/body/afterword` を **移行時点のメイン（`site`）側**へ。もう一方は空 |
| `chapterId` | `null`（未分類）。存在しない章 ID も `null` |
| `freeMemo` | 空文字 |
| `workId` | 新しい UUID |
| `site` | 不正・未設定は `narou` |
| 未知のフィールド | そのまま残す（作品・エピソード・章・表の行） |

## 安全策
- 移行は読込時に**メモリ上**で行い、元のオブジェクトは変更しない（`normalize` は何度呼んでも同じ結果）。
- 端末内の作品は、編集して自動保存されたときに初めて v3 で書き込まれる。
- 起動時、v3 移行前の作品が1件でもあれば、**移行前の形のまま** IndexedDB `meta.preV3Backup` に一度だけ退避する。
  「設定」→「バックアップ」→「v3 移行前のデータを書き出す」で全体バックアップ形式のファイルとして取り出せる。
- `.json` の読込で、壊れた JSON・別形式・新しすぎる版（schemaVersion > 3）はエラーにして読み込まない（壊れた内容で上書きしない）。

## 版（versions ストア）
- エピソードの版の中身は `{ drafts, plot, freeMemo }`。旧形式の版 `{ title, foreword, body, afterword, plot }` も復元できる（メイン側へ戻す）。
- 作品全体のバックアップ版は作品スナップショット。復元時に `normalize` で v3 へ移行される。

## テスト（tests/index.html）
旧 v2 の移行（なろう／アルファ）、未知フィールド保持、順番、移行の冪等性、保存→読込の往復、v1・txt の読込、壊れた JSON、150話の性能、エピソード名。
