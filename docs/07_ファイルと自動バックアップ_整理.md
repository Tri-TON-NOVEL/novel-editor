# ファイル機能と自動バックアップ（同期）の整理

2026-10-22 時点の整理。決めることは「8. 決めること」にまとめた。

**実装状況（Ver 2026.10.22-4.0）**：このメモの内容を実装した。
- ファイルメニュー（全体／エピソード／インポート／エクスポート）と、保存先の選択（3.12）
- 自動バックアップ（`js/sync.js`：フォルダ／Google ドライブ、プレフィックス、起動時の確認、作品ごとのまとめ）
- Google のリダイレクト方式のログイン
- 3.9 の作品ごとのドライブ自動保存と、クラウドタブの保存・開くボタンの削除

計画から変えた点・足した点：
- 「この端末で書き換えたか」は、端末の時計で前回の同期時刻とくらべる（端末どうしの時計のずれで見落とさないように）。
- 自動バックアップで保存する前にも、他の端末の新しいバックアップを確かめる。両方の端末を開いたまま書いていても、上書きせずに確認する。
- 端末ごとの設定（`sync.*`・`file.*`・保存先フォルダなど）は、全体バックアップに入れず、戻すときも使わない。

## 1. 全体の考え方

| 区分 | 役割 | 置き場所 |
|---|---|---|
| 手動 | 普通のファイル保存（上書き保存・名前を付けて保存）、プレーンテキスト・作品ファイルのインポート・エクスポート | 「ファイル」メニュー |
| 手動 | なろう・アルファから出力した TXT の一括インポート | 「設定」（これまでどおり） |
| 自動 | ① いざというときに戻すためのバックアップ<br>② 複数の端末（Windows・Mac・iPhone・iPad・Android）のあいだの、楽観的な同期 | 「設定」→「自動バックアップ」 |

## 2. 「ファイル」メニュー（手動）

2026-10-22 決定：保存・読み出しは「全体（すべての作品）」と「エピソード（今開いているもの）」の2種類。上書き保存は全体だけ、名前を付けて保存はどちらにも付ける。TXT の出力は、エピソード専用ファイルとは別にエクスポートに置く。

- **全体（すべての作品・ひな型・設定をまとめた1ファイル。今の「すべてをバックアップ」の形式）**
  - 開く…：今の「バックアップから復元」と同じ。読み込む前に、今の状態を自動でバックアップ版として残す。
  - 上書き保存（Ctrl+S／⌘S）：前回保存・開いたファイルへ上書きする。
    - パソコンの Chrome／Edge では、そのファイルに直接書く。
    - iPhone・iPad などファイルを覚えておけない環境では、「名前を付けて保存」と同じ動き（共有メニュー）になる。
  - 名前を付けて保存…
- **エピソード（今開いているもの）**
  - エピソード専用ファイル（.json）：なろう用・アルファ用の両方の原稿、プロット、フリーメモをまとめる。
  - 読み出す…：今のエピソードに上書きする。確認画面を出し、上書き前の内容はエピソードの版に自動で残す。
  - 名前を付けて保存…
- **インポート…**（プレーンテキスト・作品ファイル）
  - プレーンテキスト（.txt）：今のエピソードの本文（開いている側の原稿）に読み込む。確認つきで、上書き前の内容はエピソードの版に残す。
  - 作品1つの .json（今の「ファイルを開く」で読める作品ファイル。他のエディターや古い保存から取り込む）
- **エクスポート…**（プレーンテキスト・作品ファイル）
  - プレーンテキスト（.txt）：このエピソード／全エピソード（開いている側の原稿）
  - 作品1つの .json（今の「ファイルに保存」。作品単位で渡したいとき）
  - v3 移行前のデータ（めったに使わないので、最後に置く）

**なろう・アルファから出力した TXT のインポート**（区切り・見出しの自動検出、プレビュー、重複の確認つきの一括取り込み）は、プレーンテキストとは別の機能。これまでどおり「設定」の中に残す（2026-10-22 訂正：前の版ではファイルメニューへ移すと書いていた）。

整理で消すもの・変えるもの：
- 「設定」→「インポート／エクスポート」タブは「インポート（なろう・アルファ）」タブにする。
  - 書き出しボタン（「ファイル」メニューと同じものが2か所にある）は消す。
  - なろう・アルファの TXT インポートだけを残す。
- 「設定」→「バックアップ」の「すべてをバックアップ…」と「バックアップから復元…」。それぞれエクスポートとインポートに移す。
- 「設定」→「クラウド」の「Google ドライブに保存／開く」と、3.9 で入れた作品ごとのドライブ自動保存。新しい自動バックアップと役割が重なるため（→ 8. の決めること）。

### 2-1. 保存先・読み出し元の選び方（2026-10-22 決定）

- 保存・開くとき、保存先は2つ。
  - **Google ドライブ**（API・エディター独自の画面）
  - **この端末・その他**（Windows・Mac は保存先を選ぶ画面、iPhone・iPad は共有メニュー。iCloud・OneDrive もここから）
- 「設定」で、端末ごとに選べるようにする。

  | 設定 | 動き |
  |---|---|
  | 毎回選ぶ（既定） | 保存・開くたびに「Google ドライブ／この端末・その他」を選ぶ画面を出す。前回使ったほうを目立つボタンにする |
  | Google ドライブを優先 | 選ぶ画面を出さず、すぐ Google ドライブの画面へ |
  | この端末・その他を優先 | 選ぶ画面を出さず、すぐ端末の保存画面・共有メニューへ |

- 優先にしていても、もう一方を使えるようにする。
  - 「ファイル」メニューの最後に「保存先を選んで保存…」「保存先を選んで開く…」を置く。
  - Google ドライブの画面にも「この端末・その他に保存」ボタンを置く。
- Google ドライブを設定していない端末では、選ぶ画面も設定も出さず、「この端末・その他」だけになる。
- **Google ドライブの画面**
  - ファイル名を入れる欄と、保存先フォルダ（既定は「小説エディター」）。
  - フォルダ内のファイル一覧。押すとそのファイルに上書きする（確認つき）。
  - 開くときは一覧から選ぶ（今の「Google ドライブから開く」と同じ）。
- **上書き保存** は画面を出さず、前回保存・開いた場所（端末のファイル、またはドライブのファイル）へそのまま保存する。
  - iPad でも、ドライブのファイルならボタン1つで上書き保存できる。
  - 端末のファイルを覚えておけない iPad などでは、「名前を付けて保存」と同じ動きになる。
- **ドライブ上のフォルダ**
  - 手動保存：「小説エディター」
  - 自動バックアップ：「小説エディター／自動バックアップ」

  同期が、手動で保存したファイルを他の端末のバックアップと取り違えないように分ける。
- **他の端末・OS から読めるか**
  - 読める：同じ Google アカウント、同じクライアントID で、エディターが保存したファイルなら、Windows・Mac・iPhone・iPad・Android のどれからでも一覧に出て開ける。
  - 読めない：エディター以外（パソコン版 Google ドライブ・ブラウザのドライブ画面など）で置いたファイルは、権限（drive.file）の都合で一覧に出ない。
- iPhone・iPad のホーム画面アプリでは、ログインのときにページが読み直される（リダイレクト方式）。戻ったら、もう一度「保存」を押してもらう。

iPhone・iPad での保存は、今と同じく共有メニューから「"ファイル"に保存」で行う。iCloud Drive・OneDrive・Google ドライブのどれにも保存できる。

## 3. 「設定」→「自動バックアップ」

- **保存先の方式**
  - フォルダ：普通のドライブ・フォルダ。ローカル・OneDrive・iCloud Drive・Google ドライブ（パソコン版）の同期フォルダを選べる。
  - Google ドライブ（API）：クライアントID を入れる。API キーは、フォルダを Google Picker で選ぶときだけ必要。
- **フォルダ**：方式に応じて、保存先のフォルダを選ぶ。
- **ファイル名のプレフィックス**：自由に変えられる。既定値は端末から自動で決める。

  | 端末 | 既定値 |
  |---|---|
  | Windows | `Win_` |
  | Mac | `Mac_` |
  | iPhone | `iPhone_` |
  | iPad | `iPad_` |
  | Android | `android_` |

  iPad の Safari は Mac と名乗るので、タッチ対応かどうかで見分ける。
- **ファイル名**：`プレフィックス + 日時`（例：`iPad_20261022-0915.json`）。中身にも、保存した日時・端末名・プレフィックスを入れる。
- **保存間隔・残す件数**：今と同じく設定できる。消すのは、自分のプレフィックスの古いファイルだけにする。
- **保存するタイミング**：変更があったときの保存間隔ごと、アプリを閉じる・別のアプリに切り替えるとき、作品を切り替えるとき。
- **端末に残す記録**：最後に成功したバックアップのファイル名と時刻。成功したときだけ更新する。
- **バックアップから戻す**：フォルダ内のバックアップを一覧にして選ぶ。戻す前に、今の状態を自動でバックアップする。

## 4. 起動時の確認（同期）

起動したら保存先のフォルダを調べ、いちばん新しいバックアップを、端末に記録した「最後のバックアップ」とくらべる。

| 状況 | 動き |
|---|---|
| いちばん新しいのが自分の記録と同じ | 何もしない（端末の内容をそのまま使う） |
| 他の端末のほうが新しい／この端末は前回のバックアップから変更なし | 「他の端末（iPad_… 10/22 9:15）で更新されています。読み込みますか？」→ 読み込む／やめる |
| 他の端末のほうが新しい／この端末にも未バックアップの変更あり（競合） | ⚠ 警告 → 他の端末の記録を使う／この端末の記録を使う（すぐバックアップして最新にする）／やめる |

- 「この端末に変更があるか」が分からないと、上の2行目と3行目を区別できない。そのため「最後のバックアップ以降に書き換えたか」も端末に記録する。
- 読み込む前に、端末の今の内容を自動でバックアップ版として残す（失敗しても戻せるように）。
- 読み込み方（全部入れ替えるか、作品ごとに新しいほうを残すか）は → 8. の決めること。

## 5. 技術上の制約（重要）

### 5-1. フォルダ方式が使えるのはパソコンの Chrome／Edge だけ

| 端末・ブラウザ | フォルダ方式 | Google ドライブ（API） |
|---|---|---|
| Windows の Chrome／Edge | ○ | ○ |
| Mac の Chrome／Edge | ○ | ○ |
| Mac の Safari | ×（Web からフォルダに書けない） | ○ |
| iPhone・iPad | ×（iCloud Drive・OneDrive にも、Web アプリからは自動で書けない） | ○ |
| Android の Chrome（132 以降） | △ 端末内のフォルダは選べる。Google ドライブ・OneDrive のフォルダは、Android の仕組み上ほぼ選べない | ○ |

- 2026-10-22 再確認で訂正：Android の Chrome も 132 からフォルダを選べるようになった（以前は「×」と書いていた）。ただし同期の中心にはできないので、Android も同期するなら Google ドライブ（API）方式にする。
- iPhone・iPad で自動バックアップ先にできるのは、Google ドライブ（API）だけ。iCloud Drive には Web から使える API がない。OneDrive は Microsoft Graph API で同じことができる（Azure でアプリ登録が必要）ので、将来の候補。
- そのため設定画面は、iPhone・iPad では「Google ドライブ（API）」だけを選べるようにする。手動保存は、どの端末でも「ファイル」メニューから iCloud・OneDrive に保存できる。

### 5-1-2. 手動では iCloud・OneDrive に保存できるのに、自動ではできない理由

| | 手動（共有メニュー →「"ファイル"に保存」） | 自動 |
|---|---|---|
| 書き込むのは誰か | iOS の「ファイル」アプリ。iCloud・OneDrive・Google ドライブのアプリが、保存先として手を貸す | エディター（Web アプリ）自身 |
| 保存先を決めるのは | 毎回、人が画面で選ぶ | 一度決めた場所へ、人の操作なしで |
| Web アプリに許されているか | ○ ファイルを1つ渡すだけ（ボタンを押した直後に限る） | × iOS の Safari には、フォルダを覚えておいて後から書き込む仕組み（File System Access API）がない |

- 手動保存では、エディターは「ファイルを1つ渡す」だけで、どこにどう書くかは iOS と各クラウドのアプリが担当している。
- 自動保存では、エディターが自分で書き込み先を覚えて書く必要があるが、iPhone・iPad の Web アプリにはその権限がない（ボタンを押したとき以外は共有メニューも出せない）。
- 起動時に「フォルダの中の他の端末のバックアップを見る」ことも、同じ理由で iPhone・iPad ではできない。
- パソコンの Chrome／Edge には、この仕組み（フォルダを覚えて後から書く）があるので、OneDrive・iCloud Drive の同期フォルダに自動で書ける。
- Google ドライブ（API）は、ファイルではなく通信でドライブに直接書くので、iPhone・iPad でも自動でできる。OneDrive も同じ方法（Microsoft Graph API）なら可能。iCloud Drive にはその手段がない。

### 5-2. 同期の中心は Google ドライブにそろえる必要がある

iPad を同期に入れるなら、全端末の保存先を Google ドライブにそろえる。Windows が OneDrive、iPad が Google ドライブでは、互いのファイルが見えない。

さらに、今の権限（drive.file）では、アプリ自身が作ったファイルしか読めない。パソコンが「Google ドライブ（パソコン版）の同期フォルダ」にフォルダ方式で書いたファイルは、iPad からは見えない。対策は次のどちらか（→ 8. の決めること）。
- **A（推奨）**：iPad と同期するパソコンも「Google ドライブ（API）」方式にする。drive.file のままで、全端末のファイルがアプリで作ったものになる。Google の警告画面も出ない。
- **B**：権限に drive.readonly（ドライブ全体の読み取り）を加える。フォルダ方式のパソコンのファイルも読めるが、ログイン時に「確認されていないアプリ」の警告が出る（個人利用なら使える）。

### 5-3. ログインは約1時間で切れる

- サーバーを持たない Web アプリでは、長く使えるログイン（リフレッシュトークン）を受け取れない。
- 1時間たつと自動バックアップが止まる。上に「再ログイン」を出し、押せばすぐ続きを保存する（3.9 と同じ方式）。
- 起動時の確認にもログインが要る。1時間以内に開き直したときは、残っているログインで確認できる。それ以外は「ログインして確認」を押してもらう。

### 5-4. 「閉じるとき必ずバックアップ」は保証できない

- iPhone・iPad、とくにホーム画面のアプリは、閉じる・切り替えるとすぐに止まる。通信や書き込みが最後まで終わる保証がない。
- 対策：
  - 切り替えたとき（visibilitychange）と閉じるとき（pagehide）の両方で、すぐ保存を始める。
  - 書いている間の保存間隔も短めにする。
  - 端末の記録は成功したときだけ更新し、失敗したら次の起動時にまず保存する。
- これで「最後のバックアップが古いままになる」ことは防げる。ただし、閉じた瞬間の分が他の端末に届かないことはありうる。

### 5-5. Safari とホーム画面アプリは、データが別

iPhone・iPad では、Safari で開いたエディターと、ホーム画面から開いたエディターは、作品データも設定も別々に持つ。「ブラウザでは設定してあるのに、アプリでは設定されていない」と見えることがある。

## 6. iPad で Google ドライブがうまくいかない原因（参考アプリとの比較）

参考：`SecureVideoPlayer/dist/index.html` の Google ドライブ部分（うまく動いているもの）

| 点 | 小説エディター（今） | 参考アプリ |
|---|---|---|
| ホーム画面アプリ（PWA）でのログイン | ポップアップで開く | ポップアップを使わず、ページごと Google に移動してログインし、戻ってくる（リダイレクト方式） |
| ポップアップが開けなかったとき | エラーで終わる | `popup_failed_to_open` を受けたらリダイレクト方式に切り替える |
| ログインの部品を読み込むタイミング | ボタンを押してから読み込む場合がある | 同じだが、PWA ではポップアップを使わないので影響しない |
| API キー・Picker | フォルダ選びに使う | 使わない（自前のフォルダ一覧） |

原因と考えられるもの：
1. **PWA ではポップアップのログインが戻ってこない**：ホーム画面のアプリから開いたポップアップは、別の画面（Safari）で開かれ、ログイン結果がアプリに返らないことがある。「ブラウザだと動くが、アプリにすると駄目」に当たる。
2. **うまくいく時といかない時がある**：ボタンを押してから Google の部品を読み込み終わるまで待つと、Safari が「ボタンを押した直後」と見なさなくなり、ポップアップをブロックする。2回目（部品が読み込み済み）だと動く、ということが起きる。
3. **Google Picker も PWA では不安定になりやすい**：Safari が他のサイトの Cookie を制限するため。

直し方：
- 参考アプリと同じく、PWA ではリダイレクト方式でログインする。ブラウザでもポップアップが開けなければリダイレクト方式に切り替える。リダイレクトでページが読み直されても、作品は端末に保存済みなので消えない。
- Google Cloud Console の OAuth クライアントに「承認済みのリダイレクト URI」として、公開 URL（例：`https://ユーザー名.github.io/リポジトリ名/`）を追加する（設定作業が1つ増える）。
- 保存先フォルダは、アプリが作る「小説エディター／バックアップ」を既定にして、Picker なしでも使えるようにする。Picker（API キー）はパソコンで別のフォルダを選びたいときだけにする。

## 8. 決めること（2026-10-22：すべて推奨のほうに決定）

決定内容：同期は作品ごとに新しいほうを使う／3.9 のドライブ自動保存と「クラウド」タブは統合して削除／PC も Google ドライブ（API）方式／版はそのまま残す。
