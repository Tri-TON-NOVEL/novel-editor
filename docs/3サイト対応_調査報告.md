# 3サイト対応（なろう・カクヨム・アルファポリス）調査報告と改良方針

調査日: 2026-11-19 ／ 対象: あや綴り 0.95（APP_VERSION 2026.11.19-0.95、sw v159）

この文書はプログラムを変更する前の調査結果と方針です。**プログラムはまだ何も変更していません。**

---

## 1. 現在のデータ構造

- 保存先: IndexedDB（`projects`／`versions`／`meta`）。画面の設定は localStorage（`novel-editor:` で始まる名前）。
- 作品データ（`js/format.js`、データ形式 `schemaVersion: 3`）

```
project = {
  workId, title, synopsis,
  site: 'narou' | 'alpha',          … メインのサイト
  narouUrl, alphaUrl, narouNcode, alphaWorkId,
  chapters: [{ id, title, plot }],   … 章（1階層のみ）
  episodes: [{
    id, chapterId,
    drafts: { narou: {title, foreword, body, afterword}, alpha: {…} },  … サイト別原稿
    plot, freeMemo,                  … サイト共通
    editionIds: { narou: 稿ID, alpha: 稿ID }, siteUpdatedAt, importKeys, report,
  }],
  memos, world, characters, foreshadows, reports: { x, narouTitle, narouBody },
}
```

- サイトの一覧は `SITE_KEYS = ['narou', 'alpha']` の1か所で決まっています。
- 古いデータの読み込み時の補完は `normalize()` が行います。

既存の作りで、3サイト化に**有利な点**:
- `migrateEpisode` は、知らないサイトの原稿（例 `drafts.kakuyomu`）を捨てずに残します。
- `normalize` は、知らない項目（例 `sites`、章の `level`）をそのまま残します。
- そのため、追加する項目は、古い版で読んでも消えにくい形です。

**注意点**:
- 古い版は `site` が `narou`/`alpha` 以外だと `narou` に戻します。
- メインをカクヨムにしたデータを古い版で開くと、メインがなろうに変わります。
- 対策は 9章と13章に書きました。

## 2. エディション（サイト版）管理

用語を区別します。
- **サイト版**: 1話の中の、なろう版・アルファ版の原稿。`episodes[].drafts[サイト]` に入ります。
- **稿**: 原稿の保存版。`versions` ストアの `kind:'episode'` に入ります。
- **復元ポイント**: 作品全体の保存版。`versions` ストアの `kind:'project'` に入ります。

現状の動き:
- メイン（`project.site`）と、残る1つのサブ（`subSite()`）の2つに固定されています。
- サイトのタブは2つ固定です。サブのタブは設定で隠せます（`hide-sub-site`）。
- コピーは「メイン → サブ」の一方向だけです（`copy-main-to-sub`、`runSiteCopy`）。
  - コピー時に書式を変換します（`convertText(from, to)`）。
  - 0.89 からは、コピー先の挿入画像を残す対応付けも行います。
- 稿はサイトごとに持っています（`editionIds[サイト]`）。

## 3. 章・話の管理構造

- 章は `chapters` 配列の1階層だけです。話は `chapterId` で章に属します。null は「未分類」です。
- 並び順は配列の順で、保存時に `order` を振り直します。
- 全体プロット・伏線・横断検索・目次表示・TXT インポートは、すべてこの1階層を前提にしています。

## 7. 推奨データ構造（データ形式 v4）

既存の項目名はそのまま残し、**足すだけ**にします。古い版で読んでも消えないようにするためです。

```
project = {
  site: 'narou' | 'kakuyomu' | 'alpha',     … メイン（従来どおり。sites の中の1つ）
  sites: ['narou', 'alpha'],                 … 新規。使うサイト（1〜3個、並び順＝タブの順）
  narouUrl, alphaUrl, narouNcode, alphaWorkId,  … 従来どおり
  kakuyomuUrl, kakuyomuWorkId,               … 新規
  kakuyomu: { catchphrase, tags: [] },       … 新規（カクヨム固有の作品情報。必要なら）
  shortStory: false,                         … 新規（短編。後述）
  chapters: [{ id, title, plot, level }],    … level を追加。1＝部（大見出し）、2＝章（小見出し）。なければ 2
  episodes: [{
    drafts: { narou, kakuyomu, alpha },      … kakuyomu を追加（形は同じ4項目）
    editionIds: { narou, kakuyomu, alpha }, siteUpdatedAt: { … },  … キーが増えるだけ
    …従来どおり
  }],
}
```

- **部・章は「level 付きの平らな並び」にします。**
  - `parentId` で入れ子にする方法もあります。ですが平らな並びなら、古い版では「部」も普通の章に見えるだけで、壊れません。
  - 並べ替え・目次・既存の章処理もほぼそのまま使えます。
  - 部を使わない作品は、今と全く同じです。
  - 話は、部の直下にも章の下にも置けます（`chapterId` が部を指してもよい）。
- **使っていないサイトの原稿は消しません。**
  - サイトを外すと、`sites` から外れるだけです。タブなどには出ませんが、`drafts` には残ります。
  - もう一度追加すれば、元の原稿が戻ります。
  - 完全に消す操作は、別の確認付きにします。
- **メインは `sites` の中から選びます。** メインを外すときは、先に別のサイトをメインにしてもらいます。
- 画面の設定（タブの表示など）は、今と同じく localStorage に置き、作品データには入れません。

## 8. 推奨 UI

- **作品設定**
  - 「使うサイト」の3つのチェックと、メインの選択を置きます。
  - URL・作品ID の欄は、使うサイトの分だけ出します。
- **サイトのタブ**
  - 使うサイトだけを、`sites` の順に出します。メインに印を付けます（今と同じ）。
  - 「サブのタブを隠す」設定は「メイン以外を隠す」に読み替えます。
- **コピー**
  - 「メイン → サブ」ボタンを「ほかのサイト版へコピー…」に変えます。
  - 押すと、コピー元とコピー先（複数可）を選ぶダイアログが出ます。
    - 初期値は「表示中のサイト → ほかの全部」です。
  - その後は、今の確認・画像の対応付け（0.89）・書式変換をそのまま使います。
  - 使うサイトが2つだけのときは、今と同じ1回の操作で済むようにします。
- **章**
  - 章を作るときに「部」か「章」かを選べるようにします。
  - 一覧で、部を少し大きく表示し、章を字下げします。
  - 全体プロットも同じ並びにします。
- **インポート**
  - 取り込み元に「カクヨム（バックアップ ZIP）」を足します。実ファイルの入手後です。
- **カクヨムで使えない欄**（前書き・後書き）
  - カクヨムのタブでは隠します。
  - ほかのサイトからコピーしたときは、本文の前後に入れるかどうかを、コピーのダイアログで選べるようにします（案）。
- **定型文**
  - 「なろう用／アルファ用」に「カクヨム用」を足します。
  - タイトル欄を持つかどうかは、サイトモジュールが返すようにします。

## 9. 既存データの移行

- 作品を読み込むときに `normalize()` で補完します。今の方式と同じです。
  - `sites` がなければ `['narou', 'alpha']` にします。今の作品は2サイトを使っている扱いで、見た目も変わりません。
  - `chapters[].level` がなければ 2（章）にします。
  - `drafts.kakuyomu` は、使うサイトに加えたときに空で作ります。
- **移行前の写し**
  - v3 → v4 で初めて保存する前に、作品ごとに復元ポイント（`kind:'project'`）を1つ作ります。理由は「データ形式更新前」です。
- **古い版との行き来**（クラウド同期・バックアップ）
  - 方針1（推奨）: `schemaVersion` を 4 に上げます。
    - 古い版は v4 のファイルを「新しい版のデータです」と言って開きません。この仕組みは `format.js`・`backup.js`・`archive.js` にすでにあります。
    - 黙って壊すより安全です。
  - 方針2: v3 のままにします。
    - 古い版でも開けます。ただしメインがカクヨムの作品は、メインがなろうに変わります。
  - **正式公開前なので、方針1を推奨します。** 複数の端末を使う場合は、全端末を更新してもらう必要があります。

## 10. 既存機能への影響

| 機能 | 影響 |
|---|---|
| 本文編集・文字数・プレビュー | サイトモジュール経由になるだけで、なろう・アルファの結果は同じ |
| 書式変換（なろう⇔アルファ） | 変換表をサイトモジュールへ移すだけ。既存のテスト 62件で、結果が変わらないことを確かめる |
| コピー・画像の対応付け | 行き先が複数になる。対応付けの処理そのものは共通で使える |
| TXT インポート（なろう・アルファ） | 中身は変えない。取り込み先のサイトの選び方だけ3択になる |
| バックアップ復元・自動バックアップ・クラウド | 中身は作品データをそのまま入れているので、形の変更は不要。schemaVersion の確認だけ |
| 稿・復元ポイント | キーが増えるだけで、変更不要 |
| 横断検索 | 対象のサイトの選択肢が3つになる |
| 全体プロット・伏線・目次 | 部（level 1）の表示を足す |
| 活動報告（`reports.narouTitle` など） | なろう専用のまま残す |
| マニュアル | サイト名の記述と、図の撮り直しが必要 |

## 11. 小説保存ファイルとバックアップファイルの書式は共通か

**共通ではありません。** ただし、中に入る作品データ（project）の形は同じです。

| | 小説保存ファイル | バックアップ |
|---|---|---|
| 拡張子 | `.json` | `.ayabackup` |
| 形式名 | `format: 'novel-editor'` | `format: 'ayatuzuri-block-backup'`（旧形式は `ayatuzuri-backup-pack`） |
| 中身 | 1作品の project | 複数作品・話ごとの差分・作品ごとの情報 |

- どちらも `schemaVersion` を持っています。
- どちらも読み込み時に同じ `normalize()` を通ります。
- そのため今回のデータ形式の変更は、**`format.js` 1か所の移行処理で、両方に効きます**。
- バックアップの外側の形式（`version`）は、変える必要はない見込みです。
- 機密情報（トークン類・クライアントID）がバックアップに入らないことは、今の仕組みのまま変わりません。

## 13. リスクと対策

| リスク | 対策 |
|---|---|
| app.js（6313行）の変更範囲が大きく、思わぬ所が壊れる | サイトの判断をすべて `js/sites/` に集めてから、app.js の呼び出しを置き換える。段階ごとに既存テストとモック画面で確認する |
| 移行でデータを失う | 足すだけの移行にする。移行前に復元ポイントを作る。移行のテストを追加する（v3 の実データ → v4 → 内容が同じ） |

## 14. 実装の方針と順序（確認後に着手）

1. **サイトモジュール化**（見た目・動作は変えない）
   - `js/sites/` を作り、なろう・アルファの記法と変換を移します。`notation.js` は窓口だけにします。
   - 既存テストが全部通ることを確認します。
2. **データ形式 v4**
   - `sites`、`level`、`kakuyomu*` を追加し、`normalize` で移行します。移行前の復元ポイントも作ります。
   - 移行のテストを追加します。
3. **2サイト前提の除去**
   - `subSite`／`other` を、`sites` を使う処理に置き換えます。
   - タブ・作品設定・横断検索・定型文を対象にします。
4. **カクヨムのサイトモジュール**
   - 記法（ルビ・傍点）、3方向の変換、文字数、前書き・後書きなしの扱いを作ります。
5. **コピー**
   - コピー元・コピー先を選べるダイアログにします。画像の対応付けは既存の処理を使います。
6. **部・章の2階層**
   - 章の一覧、全体プロット、目次、TXT インポートの章の見分けに入れます。
7. **短編**
   - 1話だけで、章を出さない表示にします。
8. **カクヨム ZIP インポート**
   - 実ファイルを入手してから作ります。
9. **マニュアル・README・図の更新**

各段階で版を上げ、テストとモック画面で確認します。実機での確認が必要な項目は、そのつど分けて報告します。

### 確認していただきたいこと

1. **部・章とカクヨムの見出しの対応**
   - 部を使わない作品の「章」は、カクヨムでは大見出し・小見出しのどちらにしますか。
   - 案: 部があれば 部＝大見出し・章＝小見出し、部がなければ 章＝大見出し。
2. **古い版との互換**
   - schemaVersion を 4 に上げて、古い版では開かないようにしてよいですか（推奨）。
3. **前書き・後書き**
   - カクヨム版へコピーするとき、前書き・後書きはどう扱いますか。
   - 案: 既定は「入れない」、選べば本文の前後に入れる。
4. **カクヨム固有の作品情報**
   - キャッチコピー・タグを、作品設定に持たせますか。
5. **カクヨムのバックアップ ZIP**
   - 実物を1つ用意していただけますか。部・章・ルビ・傍点を含む、テスト用の作品が理想です。
